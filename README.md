# Нейросетевой синтез фазового ДОЭ на 4 плоскости (128×128)

Решение хакатон-задачи: по **четырём** изображениям 128×128 нейросеть за один
прямой проход формирует **один** фазовый дифракционный оптический элемент (ДОЭ)
128×128. При восстановлении по Френелю (один FFT) на расстояниях 24,1 / 25,3 /
26,5 / 27,7 мм на каждом расстоянии фокусируется своё изображение.

Решение запускается в Docker: ставить Python и библиотеки вручную не нужно.

## Как работает решение

Параметры задачи (зашиты в код и в чекпоинт):

| Параметр | Значение |
|---|---|
| Размер ДОЭ и изображений | 128×128 пикселей |
| Тип ДОЭ | фазовый, значения от −π до π |
| Длина волны | 532 нм |
| Пиксель ПВМС | 10 мкм |
| Расстояния | 24,1; 25,3; 26,5; 27,7 мм |

Конвейер:

1. **Сеть** (`model.py`, U-Net `PhaseDOEUNet`). Вход: тензор `[B, 4, 128, 128]`,
   четыре изображения как четыре канала. Выход: одна карта фазы `[B, 128, 128]`
   в диапазоне [−π, π]. Сеть предсказывает `sin φ` и `cos φ` и берёт `atan2`,
   поэтому на границе −π/+π нет разрыва.
2. **Физическая модель** (`propagation.py`, `FresnelPropagator`). Дифференцируемый
   расчёт дифракции Френеля через одно преобразование Фурье на всех четырёх
   расстояниях. Реализован на PyTorch, поэтому градиент проходит от ошибки
   восстановления обратно в сеть.
3. **Обучение** (`train.py`) без готовых «правильных» ДОЭ: сеть выдаёт фазу,
   модель Френеля восстанавливает 4 изображения, функция потерь — MSE между
   восстановленными и целевыми амплитудами, каждая предварительно
   L2-нормирована (сравнивается форма, а не абсолютная мощность).
   Обучающие данные: MNIST, ресайз до 128×128, четвёрки случайных цифр
   (`mnist_dataset.py`).
4. **Инференс** (`infer.py`): загрузка весов, один прямой проход, сохранение
   ДОЭ в 8-битный PNG (−π → 0, +π → 255), расчёт Френеля **по сохранённому
   квантованному ДОЭ**, сохранение восстановленных изображений и метрик
   (Pearson, SSIM).

## Состав репозитория

```text
.
├── Dockerfile                     # сборка контейнера
├── requirements.txt               # зависимости Python
├── README.md
├── model.py                       # нейросеть (U-Net)
├── propagation.py                 # дифференцируемая дифракция Френеля
├── train.py                       # обучение
├── infer.py                       # инференс: 4 PNG -> ДОЭ + восстановления + метрики
├── mnist_dataset.py               # обучающий набор (MNIST по 4 цифры)
├── dataset.py                     # загрузчик pic1.png ... pic4.png
├── classical_multi_plane_doe.py   # классический метод Гершберга–Сакстона (для сравнения)
├── check_install.py               # быстрая проверка модели и физики
├── main.py                        # единая точка входа: train / infer / classical ...
├── checkpoints/
│   ├── best.pt                    # обученные веса (6 МБ)
│   └── history.csv                # история обучения
└── examples/
    ├── input/                     # пример входа: pic1.png ... pic4.png
    └── expected_output/           # пример того, что должно получиться
```

Обученные веса лежат прямо в репозитории (`checkpoints/best.pt`), скачивать
их отдельно не нужно. Датасет MNIST в репозитории не хранится: для инференса он
не нужен, а `train.py` скачивает его сам.

## Быстрый старт в Docker

Нужен установленный и запущенный Docker (на Windows и macOS — Docker Desktop).

### 1. Клонировать репозиторий

```bash
git clone https://github.com/EL-Rolan/Nuclear-IT-hack.git
cd Nuclear-IT-hack
```

### 2. Собрать образ

```bash
docker build -t doe-nn .
```

Первая сборка скачивает PyTorch (CPU-версию) и занимает несколько минут.
Если файла `checkpoints/best.pt` нет, сборка остановится с понятной ошибкой.

### 3. Запустить на примере

Linux / macOS / Git Bash:

```bash
docker run --rm \
  -v "$(pwd)/examples/input:/data/input:ro" \
  -v "$(pwd)/output:/data/output" \
  doe-nn
```

Windows PowerShell:

```powershell
docker run --rm `
  -v "${PWD}\examples\input:/data/input:ro" `
  -v "${PWD}\output:/data/output" `
  doe-nn
```

Что здесь происходит: `-v` подключает папки компьютера к контейнеру.
Всё, что лежит в `examples/input`, контейнер видит как `/data/input`, а всё,
что он записывает в `/data/output`, появляется у вас в папке `output`.
Образ с кодом и весами при этом не меняется.

Результат появится в папке `output/`: `doe.png`, `doe_phase_radians.npy`,
`reconstructed_1.png` … `reconstructed_4.png`, `metrics.csv`. Метрики также
печатаются в консоль.

Дополнительные флаги дописываются после имени образа, например
`doe-nn --resize` (привести входные картинки к 128×128, если они другого размера).

## Обработка нескольких комплектов

Каждый комплект — отдельная папка с файлами `pic1.png` … `pic4.png`:

```text
sets/
├── set1/   pic1.png pic2.png pic3.png pic4.png
├── set2/   pic1.png pic2.png pic3.png pic4.png
└── ...
```

Linux / macOS / Git Bash:

```bash
for d in sets/*/; do
  name=$(basename "$d")
  docker run --rm \
    -v "$(pwd)/sets/$name:/data/input:ro" \
    -v "$(pwd)/out/$name:/data/output" \
    doe-nn
done
```

Windows PowerShell:

```powershell
Get-ChildItem sets -Directory | ForEach-Object {
  docker run --rm `
    -v "$($_.FullName):/data/input:ro" `
    -v "${PWD}\out\$($_.Name):/data/output" `
    doe-nn
}
```

На каждый комплект получается свой `out/<имя комплекта>/doe.png`.
Порядок файлов важен: `pic1` относится к расстоянию 24,1 мм, `pic2` — к 25,3 мм,
`pic3` — к 26,5 мм, `pic4` — к 27,7 мм.

## Формат входа и выхода

**Вход:** папка с четырьмя файлами `pic1.png` … `pic4.png`; каждый — PNG,
128×128, одноканальный 8-битный (цветные файлы автоматически переводятся в
оттенки серого).

**Выход** (папка `/data/output` в контейнере):

| Файл | Содержимое |
|---|---|
| `doe.png` | ДОЭ: PNG, 128×128, 8 бит, grayscale; −π → 0, +π → 255 |
| `doe_phase_radians.npy` | та же фаза в радианах (до квантования), справочно |
| `reconstructed_1.png` … `_4.png` | модули восстановленных полей на 4 расстояниях, 128×128, 8 бит, нормированы на максимум |
| `metrics.csv` | Pearson и SSIM по каждой плоскости, расстояние, шаг пикселя в плоскости восстановления |

## Пример

Вход `examples/input/` — четыре цифры MNIST (5, 0, 4, 1). Файлы, полученные
на этом входе, лежат в `examples/expected_output/`. Метрики из
`examples/expected_output/metrics.csv`:

| Плоскость | z, мм | Pearson | SSIM |
|---|---|---|---|
| 1 | 24,1 | 0,702 | 0,139 |
| 2 | 25,3 | 0,686 | 0,164 |
| 3 | 26,5 | 0,457 | 0,151 |
| 4 | 27,7 | 0,588 | 0,150 |
| среднее | | 0,608 | 0,151 |

Это результаты модели, обученной 5 эпох (`checkpoints/history.csv`), на одном
примере; метрики считаются в `infer.py` по нормированным на максимум
изображениям и могут отличаться от метрик проверяющих.

## Обучение (необязательно)

Для проверки решения обучение не требуется: веса уже в репозитории.
Чтобы переобучить модель, нужен доступ в интернет (скачивается MNIST).

В Docker (веса и данные сохраняются на вашем компьютере):

```bash
docker run --rm \
  -v "$(pwd)/data:/app/data" \
  -v "$(pwd)/checkpoints:/app/checkpoints" \
  --entrypoint python doe-nn train.py --epochs 10 --batch-size 4
```

Полезные параметры `train.py`: `--epochs`, `--batch-size`, `--learning-rate`
(по умолчанию 1e-4), `--base-channels` (по умолчанию 32), `--device`
(`auto`, `cpu`, `cuda`), `--max-train-samples` и `--max-test-samples`
(быстрый пробный прогон), `--representation amplitude|intensity`.
Лучший по тестовой потере чекпоинт сохраняется в `checkpoints/best.pt`,
последний — в `checkpoints/last.pt`, история — в `checkpoints/history.csv`.

Быстрая проверка, что весь конвейер работает (1 эпоха на малой выборке):

```bash
docker run --rm --entrypoint python doe-nn train.py \
  --epochs 1 --batch-size 2 --max-train-samples 8 --max-test-samples 4 \
  --output-dir /tmp/ckpt
```

## Запуск без Docker

Нужен Python 3.10 или 3.11.

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\Activate.ps1
pip install -r requirements.txt

python infer.py --input-dir examples/input --output-dir output --checkpoint checkpoints/best.pt
```

То же через единую точку входа: `python main.py infer --input-dir examples/input`.
Проверка установки (сравнение PyTorch-модели Френеля с NumPy-версией и проверка
градиентов): `python check_install.py`.

## Классический метод для сравнения

`classical_multi_plane_doe.py` — итеративный многоплоскостной алгоритм
Гершберга–Сакстона (NumPy, без нейросети). Ему нужны `pic1.png` … `pic4.png`
рядом со скриптом; результаты пишутся в `results/`. Он служит эталоном
для сравнения качества и времени работы с нейросетью.

```bash
cp examples/input/pic*.png .
python classical_multi_plane_doe.py
```

## Ограничения

- Модель обучена на цифрах MNIST. Качество на изображениях другого типа
  (сложные объекты, текстуры) может быть ниже.
- Обучение физически информированное: готовых «эталонных» ДОЭ нет, ошибка
  считается после дифференцируемого расчёта дифракции.
- Метод Френеля с одним FFT даёт разный шаг пикселя в плоскостях
  восстановления (`dx = λ·z / (N·dx_in)`, от ≈10,0 до ≈11,5 мкм); это учтено в
  расчёте, но не в самих входных изображениях.
- Входные файлы должны называться `pic1.png` … `pic4.png`.

## Частые проблемы

- **`Input image not found`** — в папке, подключённой как `/data/input`, нет
  одного из файлов `pic1.png` … `pic4.png`, либо путь в `-v` указан неверно.
- **`has size ..., expected (128, 128)`** — добавьте флаг `--resize` после
  имени образа.
- **`ОШИБКА: нет checkpoints/best.pt` при сборке** — файл весов не попал в
  репозиторий; проверьте `git ls-files checkpoints`.
- **`Cannot connect to the Docker daemon`** — запустите Docker Desktop.
- **Пустая папка `output` на Windows** — проверьте, что диск, на котором лежит
  проект, разрешён для общего доступа в настройках Docker Desktop.
