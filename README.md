# Нейросетевой синтез фазового ДОЭ для четырёх плоскостей

Проект формирует **один фазовый дифракционный оптический элемент (ДОЭ) размером 128×128 пикселей** по четырём входным изображениям. Нейросеть получает все четыре изображения одновременно как четыре канала входного тензора, предсказывает фазу ДОЭ, а затем программа рассчитывает восстановленные изображения на четырёх расстояниях по формуле дифракции Френеля.

Основной способ запуска — Docker. Для инференса не требуется устанавливать Python или библиотеки на хост-компьютер: достаточно установленного Docker и подготовленных весов модели.

## Параметры задачи

| Параметр | Значение |
|---|---:|
| Размер входных изображений | 128×128 пикселей |
| Количество входных изображений | 4 |
| Количество выходных ДОЭ | 1 |
| Размер ДОЭ | 128×128 пикселей |
| Представление ДОЭ | Фаза в диапазоне от −π до +π |
| Формат итоговой ДОЭ | PNG, 8 бит, grayscale |
| Длина волны | 532 нм |
| Шаг пикселя ДОЭ | 10 мкм |
| Расстояния восстановления | 24,1; 25,3; 26,5; 27,7 мм |

Порядок входных изображений фиксирован:

| Файл | Расстояние распространения |
|---|---:|
| `pic1.png` | 24,1 мм |
| `pic2.png` | 25,3 мм |
| `pic3.png` | 26,5 мм |
| `pic4.png` | 27,7 мм |

```text
Genii4.2/
├── .dockerignore          # исключения из контекста сборки Docker
├── Dockerfile             # сборка контейнера и команда инференса по умолчанию
├── README.md              # описание и инструкции
├── requirements.txt       # Python-зависимости проекта
├── model.py               # нейросеть PhaseDOEUNet (U-Net)
├── propagation.py         # дифференцируемое распространение Френеля на PyTorch
├── infer.py               # инференс: 4 изображения -> 1 ДОЭ -> 4 восстановления
├── train.py               # обучение нейросети
├── mnist_dataset.py       # генерация обучающих четвёрок изображений MNIST
├── dataset.py             # загрузчик и проверки входного набора изображений
├── GS.py                  # классический алгоритм Gerchberg–Saxton для сравнения
├── main.py                # диспетчер команд проекта (в т. ч. train и infer)
└── checkpoints/
    └── best.pt            # обученные веса; обязательны для сборки и инференса
```

Каталог `checkpoints/` создаётся при обучении. Для сдаваемой версии файл `checkpoints/best.pt` необходимо добавить в репозиторий и убедиться, что Git отслеживает его. Dockerfile проверяет наличие этого файла во время сборки и завершает сборку с ошибкой, если весов нет.

Каталоги `data/`, `output/` и `results/` создаются при необходимости и не должны содержать обязательные для инференса библиотеки или исходный код.

## Как работает решение

1. `infer.py` загружает `pic1.png`, `pic2.png`, `pic3.png` и `pic4.png`, преобразует их в 8-битный grayscale и нормирует значения в диапазон `[0, 1]`.
2. Четыре изображения объединяются в один тензор формы `[1, 4, 128, 128]` и за один проход подаются в `PhaseDOEUNet` из `model.py`.
3. Нейросеть возвращает одну фазовую карту формы `[128, 128]` со значениями в диапазоне `[-π, +π]`.
4. Фаза кодируется в 8-битный PNG: `−π` соответствует `0`, `+π` — `255`.
5. Для проверки восстановления программа декодирует фазу именно из сохранённого 8-битного PNG и рассчитывает распространение Френеля на четырёх заданных расстояниях.
6. Сохраняются четыре восстановленных изображения и метрики Pearson и SSIM для каждой плоскости.

### Распространение Френеля и центрированная сетка

В `propagation.py` реализована дифференцируемая модель `FresnelPropagator`. Для центрированной сетки используется **прямое двумерное БПФ**:

```python
torch.fft.fftshift(
    torch.fft.fft2(
        torch.fft.ifftshift(x, dim=(-2, -1)),
        dim=(-2, -1)
    ),
    dim=(-2, -1)
)
```

То есть перед прямым `fft2` выполняется `ifftshift`, а после него — `fftshift`. В `GS.py` используется аналогичная NumPy-реализация `np.fft.fftshift(np.fft.fft2(np.fft.ifftshift(array)))`. Координаты входной и выходной сеток отсчитываются от центра массива. Выходной шаг пикселя рассчитывается по формуле:

```text
dx_out = wavelength * z / (N * dx_in)
```

где `N` — размер стороны ДОЭ, `dx_in` — шаг пикселя ДОЭ, `z` — расстояние распространения.

## Требования

Для запуска в контейнере:

- установленный Docker или Docker Desktop;
- файл обученных весов `checkpoints/best.pt` в репозитории;
- четыре входных PNG-файла требуемого формата.

Для запуска Python-скриптов непосредственно на компьютере требуется Python 3.10 или 3.11 и зависимости из `requirements.txt`.

## Быстрый запуск в Docker

### 1. Клонирование репозитория

```bash
git clone https://github.com/EL-Rolan/Genii4.2.git
cd Genii4.2
```

### 2. Проверка наличия весов

До сборки контейнера проверьте, что файл весов присутствует:

```bash
ls -lh checkpoints/best.pt
```

Если файла нет, сначала обучите модель (см. раздел «Обучение модели»), затем добавьте полученный `checkpoints/best.pt` в репозиторий. Без этого файла сборка Docker намеренно завершится ошибкой.

### 3. Сборка Docker-образа

```bash
docker build -t genii-doe .
```

В Dockerfile используется Python 3.11 и CPU-версия PyTorch. Отдельная установка Python и библиотек на хост-компьютере для инференса не нужна.

### 4. Подготовка входного комплекта

Создайте каталог, например `test_data/set_01/`, и положите в него четыре изображения:

```text
test_data/
└── set_01/
    ├── pic1.png
    ├── pic2.png
    ├── pic3.png
    └── pic4.png
```

Каждый файл должен иметь размер 128×128 пикселей. Цветные изображения автоматически преобразуются в grayscale. Если размеры отличаются, по умолчанию программа сообщит об ошибке; для принудительного изменения размера используйте флаг `--resize`.

### 5. Запуск на одном комплекте

Linux / macOS / Git Bash:

```bash
mkdir -p output/set_01
docker run --rm \
  -v "$(pwd)/test_data/set_01:/data/input:ro" \
  -v "$(pwd)/output/set_01:/data/output" \
  genii-doe
```

Windows PowerShell:

```powershell
New-Item -ItemType Directory -Force output\set_01 | Out-Null
docker run --rm `
  -v "${PWD}\test_data\set_01:/data/input:ro" `
  -v "${PWD}\output\set_01:/data/output" `
  genii-doe
```

Если изображения нужно привести к размеру 128×128, добавьте `--resize` после имени образа:

```bash
docker run --rm \
  -v "$(pwd)/test_data/set_01:/data/input:ro" \
  -v "$(pwd)/output/set_01:/data/output" \
  genii-doe --resize
```

### 6. Запуск на пяти и более комплектах

Каждый комплект хранится в отдельном каталоге и содержит собственные `pic1.png`–`pic4.png`:

```text
test_data/
├── set_01/
│   ├── pic1.png
│   ├── pic2.png
│   ├── pic3.png
│   └── pic4.png
├── set_02/
│   └── ...
├── set_03/
│   └── ...
├── set_04/
│   └── ...
└── set_05/
    └── ...
```

Linux / macOS / Git Bash:

```bash
for input_dir in test_data/*/; do
  set_name=$(basename "$input_dir")
  mkdir -p "output/$set_name"
  docker run --rm \
    -v "$(pwd)/$input_dir:/data/input:ro" \
    -v "$(pwd)/output/$set_name:/data/output" \
    genii-doe
done
```

Windows PowerShell:

```powershell
Get-ChildItem test_data -Directory | ForEach-Object {
  $setName = $_.Name
  New-Item -ItemType Directory -Force "output\$setName" | Out-Null
  docker run --rm `
    -v "$($_.FullName):/data/input:ro" `
    -v "${PWD}\output\$setName:/data/output" `
    genii-doe
}
```

Для каждого комплекта результаты будут сохранены отдельно: `output/set_01/`, `output/set_02/` и так далее.

## Формат результатов

По умолчанию Docker-контейнер записывает результаты в `/data/output`. При запуске с примером выше на компьютере они появятся в `output/set_01/`.

| Файл | Содержание |
|---|---|
| `doe.png` | Итоговая фазовая ДОЭ: PNG, 128×128, 8 бит, grayscale |
| `doe_phase_radians.npy` | Фазовая карта в радианах до 8-битного квантования, NumPy float32 |
| `reconstructed_1.png` | Восстановленное изображение на расстоянии 24,1 мм |
| `reconstructed_2.png` | Восстановленное изображение на расстоянии 25,3 мм |
| `reconstructed_3.png` | Восстановленное изображение на расстоянии 26,5 мм |
| `reconstructed_4.png` | Восстановленное изображение на расстоянии 27,7 мм |
| `metrics.csv` | Pearson, SSIM, расстояние и шаг пикселя для каждой из четырёх плоскостей |

В `metrics.csv` сохраняется по одной строке на каждую плоскость. Среднее значение метрики по комплекту рассчитывается как среднее арифметическое четырёх значений соответствующего столбца `pearson` или `ssim`. Для итоговой оценки нескольких комплектов сначала усредните значения внутри каждого комплекта, затем — результаты комплектов согласно методике проверки.

## Запуск без Docker

Создайте виртуальное окружение и установите зависимости:

```bash
python -m venv .venv

# Linux / macOS / Git Bash
source .venv/bin/activate

# Windows PowerShell: вместо предыдущей команды используйте:
# .venv\Scripts\Activate.ps1

pip install -r requirements.txt
```

Запуск инференса:

```bash
python infer.py \
  --input-dir test_data/set_01 \
  --output-dir output/set_01 \
  --checkpoint checkpoints/best.pt
```

Основные аргументы `infer.py`:

| Аргумент | Назначение |
|---|---|
| `--input-dir` | Каталог с `pic1.png`–`pic4.png` |
| `--output-dir` | Каталог сохранения результатов |
| `--checkpoint` | Путь к файлу обученных весов |
| `--resize` | Изменить размер входных изображений на 128×128 |
| `--device` | Устройство вычислений: `auto`, `cpu`, `cuda` или `mps` при наличии поддержки |
| `--representation` | Интерпретация входных значений: `checkpoint`, `amplitude` или `intensity` |

## Обучение модели

Обучение реализовано в `train.py`. Используется `FourPlaneMNIST` из `mnist_dataset.py`: один обучающий элемент состоит из четырёх изображений MNIST, увеличенных до 128×128. Датасет MNIST загружается автоматически при первом запуске обучения и сохраняется в каталоге `data/`.

Пример обучения:

```bash
python train.py --epochs 10 --batch-size 4 --output-dir checkpoints
```

После обучения в `checkpoints/` создаются:

- `best.pt` — веса с наилучшей потерей на тестовой части датасета;
- `last.pt` — веса последней эпохи;
- `history.csv` — история train/test loss и learning rate.

Основные аргументы обучения: `--epochs`, `--batch-size`, `--learning-rate`, `--base-channels`, `--workers`, `--max-train-samples`, `--max-test-samples`, `--representation`, `--device`, `--seed`. Для полного списка параметров используйте:

```bash
python train.py --help
```

После обучения убедитесь, что `checkpoints/best.pt` включён в Git-репозиторий. Если веса создавались локально, но не были добавлены в коммит, на другой машине Docker-сборка не сможет их получить.

## Классический алгоритм для сравнения

В `GS.py` находится реализация многоплоскостного алгоритма Gerchberg–Saxton без нейросети. Она предназначена для сравнения с нейросетевым методом.

Скрипт ожидает файлы `pic1.png`, `pic2.png`, `pic3.png`, `pic4.png` в каталоге самого `GS.py`. Результаты сохраняются в `results/`.

Пример запуска из корня проекта после размещения четырёх входных изображений рядом с `GS.py`:

```bash
python GS.py
```

Этот классический алгоритм не является Docker-командой по умолчанию: стандартный `ENTRYPOINT` контейнера запускает `infer.py`.

## Частые проблемы

- **`ОШИБКА: нет checkpoints/best.pt` при сборке.** Добавьте обученные веса по пути `checkpoints/best.pt` и убедитесь, что файл попал в Git-коммит.
- **`Input image not found`.** Проверьте, что в подключённой папке есть все четыре файла с именами `pic1.png`, `pic2.png`, `pic3.png`, `pic4.png`.
- **`has size ..., expected (128, 128)`.** Подготовьте изображения размером 128×128 или добавьте `--resize` после имени Docker-образа.
- **Не удаётся подключиться к Docker.** Запустите Docker Engine или Docker Desktop.
- **Выходная папка пустая.** Проверьте пути в параметрах `-v` и права Docker Desktop на доступ к диску.

## Ограничения

- Обучающая выборка в текущем `train.py` основана на MNIST. Это не гарантирует высокое качество на объектах, существенно отличающихся от рукописных цифр; качество нужно отдельно проверять на целевых тестовых комплектах.
- `infer.py` записывает Pearson и SSIM отдельно для каждой из четырёх плоскостей в `metrics.csv`; автоматическое объединение результатов нескольких комплектов в один сводный CSV не выполняется.
- Dockerfile устанавливает CPU-версию PyTorch. Контейнер не требует GPU и не использует CUDA.
